# Future community benchmarks

No live leaderboard is implemented. A useful future system should reward improvement and defensible output, not raw consumption.

Potential categories: efficiency improvement against a developer’s own baseline, verified output with defensible Git/release evidence, lean build for comparable task cohorts, healthy capability utilization, versatility, and consistency.

Never rank primarily by token total, generated LOC, prompts or tool calls. Those are easy to inflate and often reward waste.

Comparisons require privacy-preserving cohorts at minimum by project type, language/ecosystem, repository size, task category and experience period. Participation should upload only user-approved, normalized snapshots; opaque methodology, minimum sample sizes, anomaly review and opt-out/deletion are mandatory.
